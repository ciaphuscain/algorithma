# Testing

```bash
npm test             # unit, property, conformance and content tests (Vitest)
npm run build:e2e && npm run test:e2e   # Playwright journeys, accessibility, mobile, sandbox (production build with the code runner on)
npm run check        # typecheck + lint + unit tests
npm run bench:trace  # trace reconstruction experiment (not a test; prints measurements)
```

Python 3 must be on `PATH` for the Python implementation tests; without it those tests are skipped and reported as skipped.

## What tests do not prove

- Passing the conformance and property suites is **empirical evidence**, not a proof of correctness. Correctness arguments are in each lesson's Mathematics level.
- Automated accessibility checks cover a subset of WCAG; screen-reader walkthroughs have not been done yet.
- Lesson prose is not verified by tests (only its maths syntax, code and numbers).
- The distributed visualizers are simplified models (no snapshots or membership changes; one failing mapper in MapReduce, lost messages but no crashes in Paxos, up to three crashes and two partitions in Raft; message delays of 1–3 time units); their checkers test safety properties on the recorded history, not on all possible executions.
- E2E runs in Chromium only; Firefox and WebKit are untested. This matters most for the code sandbox, whose isolation depends on browser behaviour.
- The sandbox tests show the boundary holds against the attacks tried; they are not an independent security review.
