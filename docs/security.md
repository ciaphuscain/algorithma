# Security model and threat register

Scope: the current release (static lessons, in-browser execution of reviewed algorithms, Studio trace import, local progress). Threats for features that do not exist yet are listed so they are designed in, not bolted on.

## Trust boundaries today

| Data                                | Trust                            | Handling                                                                                                                                              |
| ----------------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Algorithm modules, lesson content   | Trusted (code-reviewed, in repo) | Rendered as React elements; TeX through KaTeX with `trust: false`                                                                                     |
| Visualizer inputs typed by the user | Untrusted                        | Parsed by `InputSpec.parse` only: strict grammar, size and range limits, errors listed back to the user                                               |
| Imported trace JSON (Studio)        | Untrusted                        | `validateTrace`: schema, unknown-field rejection, resource limits, full semantic replay before rendering; rendered as text/SVG attributes, never HTML |
| localStorage progress               | Untrusted (user-controlled)      | Parsed defensively; shape-checked; failure falls back to empty progress                                                                               |

## Threat register

| Threat                                                            | Surface                          | Impact                                                       | Mitigation                                                                                                                                                                                                             | Residual risk                                         | Test                                          |
| ----------------------------------------------------------------- | -------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------- |
| **Untrusted code execution**                                      | Future Code/Studio editors       | Server or origin compromise, data theft, resource exhaustion | Not offered ([ADR-0003](decisions/0003-no-untrusted-execution-yet.md))                                                                                                                                                 | None today; large when enabled                        | Adversarial suite required before enabling    |
| **XSS via content or traces**                                     | Lesson text, trace labels, notes | Session/data theft                                           | React escaping; the only `dangerouslySetInnerHTML` is KaTeX output for repository TeX; trace strings are rendered as text; strict security headers                                                                     | KaTeX vulnerabilities (pinned to 0.19, audited in CI) | Content test renders all TeX; validator tests |
| **Malicious / oversized trace**                                   | Studio import                    | Tab freeze, memory exhaustion                                | Size limits before replay, 200k-event cap, one replay pass                                                                                                                                                             | Large-but-legal traces take ~0.3 s to validate        | `validateTrace` limit tests                   |
| **Malformed trace crashes app**                                   | Studio import                    | Broken page                                                  | Validator never throws (tested on garbage input); replay errors reported with event index                                                                                                                              | Renderer bugs on legal-but-unusual states             | e2e Studio tests                              |
| **Input-driven DoS**                                              | Visualizer forms                 | Frozen tab                                                   | Per-algorithm input limits (≤ 40 elements, ≤ 26 nodes); event budget                                                                                                                                                   | —                                                     | e2e validation tests                          |
| **Clickjacking**                                                  | All pages                        | UI redress                                                   | `X-Frame-Options: DENY`                                                                                                                                                                                                | —                                                     | Header check                                  |
| **Supply chain**                                                  | npm dependencies                 | Arbitrary code in build or bundle                            | Exact lockfile, `npm audit --audit-level=high` in CI, minimal dependencies (4 runtime)                                                                                                                                 | Compromised but unflagged releases                    | CI audit                                      |
| CSRF, injection, auth bypass, privilege escalation, session theft | Future API and accounts          | —                                                            | No server state yet. When added: same-site cookies + CSRF tokens on mutations, parameterised queries, server-side authorisation on every request, least-privilege roles (teachers do not see private student projects) | —                                                     | Authorization tests per route                 |
| AI prompt injection                                               | Future tutor                     | Misleading or harmful output                                 | Treat retrieved docs and user code as data; AI output labelled advisory and never used as a correctness authority                                                                                                      | —                                                     | Evaluation set incl. injection cases          |
| Malicious visualization extensions                                | Future custom renderers          | XSS, data theft                                              | Extensions would run in a sandboxed cross-origin iframe with postMessage-only access to state                                                                                                                          | —                                                     | —                                             |
| Fraudulent benchmark claims                                       | Future Arena sharing             | Misinformation                                               | Record environment and methodology; distinguish operation counts (deterministic) from wall-clock                                                                                                                       | —                                                     | —                                             |

## Security headers

Set in `next.config.ts`: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Permissions-Policy` denying camera, microphone and geolocation. A Content-Security-Policy is the next hardening step; it requires nonces for Next.js inline scripts and `style-src 'unsafe-inline'` for KaTeX and SVG positioning.
