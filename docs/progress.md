# Progress and continuation record

_Last updated 2026-10-26._

## Where things stand

ALGORITHMA has a working learning platform for 147 algorithms on one generalised trace engine, covering every Tier 1, Tier 2 and Tier 3 item of the curriculum and more, with Studio, Arena, practice with per-topic history and learning paths, exam notes, the 600-item curriculum, and a browser code sandbox that is built and tested but switched off by default. It is still an early release: accounts, community features, server-side execution and most of the long-term vision are not built.

## Backlog

Done since the previous record:

- **Review workflow** ([content-review.md](content-review.md)): a review record names the reviewer, date and scope and stores a hash of the entry's content; `npm run content:hash` prints it, and an entry changed after its review shows "Changed since expert review". The workflow exists; no review has been done.
- **Sorting views:** heap sort draws its array as a heap; merge and quick sort draw their recursion trees.
- **Learning paths and practice history:** each entry shows its prerequisites and the entries that build on it; the Progress page shows results by topic and suggests what is ready next.
- **Arena** compares sorting, searching or shortest-path algorithms on the same inputs, in a Web Worker (main thread if workers are unavailable), and checks every output.
- **Traces** export compressed (`.json.gz`); Studio imports both, with limits on the compressed and decompressed size.
- **Timelines** fade messages older than 12 time units and, when busy, can hide them.
- **Raft** scenarios take up to three crashes; the `figure8` preset shows why a leader commits only entries of its own term, and it catches the one Raft mutation that used to survive.
- **Five more fundamentals:** Shell sort, counting sort, LSD radix sort, the sieve of Eratosthenes and the extended Euclidean algorithm, each with an oracle, property tests (including stability read from the trace) and a lesson.
- **Hash tables:** separate chaining, open addressing with linear probing or double hashing (with tombstones), Robin Hood hashing (backward-shift deletion) and cuckoo hashing, whose refusals are checked against an exact feasibility test on the cuckoo graph.
- **Linked lists:** two new protocol events, `graph.link` and `graph.unlink`, let a graph's edges change during a trace; five modules re-point next fields on screen (reversal, cycle detection, merging, two-pointer techniques, random-pointer copy) with labels showing which nodes each variable points at.
- **Hash functions:** Rabin–Karp with a rolling polynomial hash (spurious hits shown and counted), consistent hashing on a drawn ring with virtual nodes, rendezvous hashing, and Zobrist hashing of board positions; the lessons report measured ring shares rather than assumed balance.
- **Stack applications:** balanced brackets, Dijkstra's shunting-yard algorithm, postfix and prefix evaluation, expression trees and the Tower of Hanoi, each checked against an independent oracle (pair deletion, a recursive-descent parser, a recursive evaluator, a legal-move replay); a property test compares shunting-yard with the parser on operator chains, where only precedence and associativity decide the grouping.
- **Queues and heaps:** a queue from two stacks (checked against the amortised bound of one transfer per item) and a stack from one queue (exact rotation count), a min/max stack whose auxiliary stack keeps repeated minimums, a circular queue that rejects or overwrites when full, a deque in a ring buffer that doubles (copies checked against capacity − 2), and a binary heap as a priority queue, drawn as a tree that grows and shrinks inside its array, with every operation checked against its O(log n) comparison bound. Random operation sequences test each one against a plain-array model.
- **Balanced search trees:** a new protocol event, `tree.rotate`, rotates a binary tree at any node, the root included. AVL (heights shown), red-black (colours shown; insert and delete fix-ups), splay (zig, zig-zig, zig-zag) and treap (priorities shown) trees run inserts, deletes and searches; Morris traversal shows its temporary threads. AA trees (levels shown) use skew and split; scapegoat trees rebuild lopsided subtrees with rotations only (Day–Stout–Warren), and every rebuilt subtree is checked to have minimum height. B-trees and B+ trees are drawn as general trees with multi-key nodes; splits and merges re-hang children with `tree.move`, and a root split keeps the root node and grows two children under it, so no new event was needed. B-tree, B+ tree and B\* tree runs are compared with independent implementations of the same rules; the B\* tree redistributes to a sibling before splitting and splits two full nodes into three. B\* tree deletion is not implemented yet. Oracles recompute AVL heights and red-black colour rules, rebuild the unique treap as a Cartesian tree, and replay an independent bottom-up splay model; property tests check the invariants after every operation of random sequences and while deleting every key.
- **Meldable heaps:** a new protocol event, `tree.swap`, exchanges two subtrees. Leftist heaps (ranks shown) and skew heaps merge along their right spines under a ⋃ placeholder that holds the heap and the incoming heap; both are compared with independent recursive merges, and the leftist heap's right spine is checked against ⌊log₂(n + 1)⌋. Binomial, Fibonacci and pairing heaps are forests drawn under a “roots” placeholder, with insert, extract-min, peek and decrease-key; Fibonacci heaps show marks and cascading cuts. Oracles: a plain set for results, binomial shape against the binary digits of n, the F(d + 2) size bound, and independent implementations of each.
- **Tries:** a radix tree (compressed trie) that splits edges on insert and merges lone children on delete, checked against the unique radix tree of the remaining words; a Patricia trie on 7-bit keys with one bit test per internal node and a single full comparison per search, checked against the unique trie of its keys; a ternary search tree with < = > branches, checked against an independent recursive insert; and a naive suffix trie whose leaves give every occurrence of a pattern, checked against brute-force matching and the number of distinct substrings.
- **Skip list and caches:** a skip list drawn as a table of levels, with reproducible coin flips per key, checked against a set and its tower heights; an LRU cache drawn as its recency list and an LFU cache drawn as buckets of recency lists by use count, each checked against an independent model (an insertion-ordered map; a scan for the fewest uses and oldest last use).
- **Searching variants:** sentinel linear search, recursive binary search (with its call stack drawn), Knuth's uniform binary search (with its step table, and virtual keys at positions 0 and n + 1), ternary search on unimodal arrays, interpolation, exponential, jump and Fibonacci search; all checked against the array and, in property tests, against their comparison bounds.
- **Elementary sorting:** optimised bubble sort (early exit and last-swap bound), cocktail shaker, comb, odd–even transposition, gnome, double selection, bingo and cycle sort; properties check one swap per inversion for the adjacent-swap sorts, cycle sort's write count, bingo sort's passes against the number of distinct values, and odd–even's phase bound.
- **Insertion and divide-and-conquer sorting:** binary insertion, library sort (gapped shelf, re-spread after each doubling), patience sort (piles drawn as stacks; pile count = LIS length), natural and bottom-up merge sort, three-way and dual-pivot quicksort; properties check shifts = inversions, the binary-insertion comparison bound, piles = LIS, merge pass counts, and at most one three-way partition per distinct value.
- **Heap and distribution sorting:** weak-heap sort (reverse bits shown), smoothsort on Leonardo heaps (root-restoring version, linear on sorted input), tournament sort on a winner tree, MSD radix, bucket (buckets as queues) and flash sort; properties check the Edelkamp–Wegener comparison bound for weak-heapsort, tournament sort's bound and smoothsort's linear cost on sorted input.
- **Partitions and the no-op entry:** the simulated network can be partitioned, and a Raft leader can append a no-op when elected; presets show a leader cut off in a minority losing its entry, and Figure 8 committing once the no-op is on.

## How to resume

```bash
npm ci
npm run check                          # typecheck, lint, 5,817 unit tests
npm run build:e2e && npm run test:e2e  # 197 Playwright tests (Chromium 1194 via @playwright/test 1.56.1)
npm run dev                            # http://localhost:3000 (add NEXT_PUBLIC_ENABLE_CODE_RUNNER=1 for the runner)
npm run bench:trace                    # trace reconstruction measurements
```

`build:e2e` enables the code runner so its adversarial suite runs; `npm run build` produces the default build with the runner off.

If `npm install` crashes with `Cannot read properties of null (reading 'edgesOut')`, that is an npm 10 resolver bug: use `npx npm@11.6.2 install` (the lockfile was produced with npm 11; `npm ci` works with npm 10).

When running e2e locally, stop any old server on port 3100 first (it shows up as `next-server`, not `next start`): Playwright reuses an existing server, and a stale one serves the previous build. Worse, it can write 404s for pages it does not know into `.next`, which then survive a restart; `rm -rf .next` and rebuild if new pages 404.

To add an algorithm, follow [adding-an-algorithm.md](adding-an-algorithm.md).
